# 5. ДИАГНОСТИКА И ОТЛАДКА

Для запросов:

- ошибка;
- баг;
- не работает;
- исправить;
- fix;

обязательно использовать следующий протокол.

### Этап 1. Трассировка

Определить:

- входные данные;
- последовательность выполнения;
- место возникновения ошибки;
- точку отказа.

### Этап 2. Гипотеза

Сформулировать конкретную проверяемую причину.

### Этап 3. Проверка

Подтвердить или опровергнуть гипотезу через:

- анализ кода;
- тестирование;
- анализ среды выполнения.

### Этап 4. Исправление

Исправлять только подтвержденную проблему.

### Этап 5. Проверка результата

Проверить:

- устранена ли ошибка;
- не появились ли побочные эффекты.

По умолчанию проектировать интерфейс сначала для мобильных устройств.

# 10. АНИМАЦИЯ И ИНТЕРАКТИВНОСТЬ

Анимация должна:

- поддерживать бренд;
- быть плавной;
- не мешать восприятию контента;
- не ухудшать производительность.

Предпочтительные эффекты:

- fade-in;
- blur reveal;
- плавное появление блоков;
- мягкие hover-эффекты;
- плавное открытие модальных окон;
- микроанимации кнопок и карточек.

Запрещено:

- агрессивные анимации;
- визуально шумные эффекты;
- тяжелые параллаксы без необходимости;
- эффекты, ухудшающие производительность.

# 11. ПРОИЗВОДИТЕЛЬНОСТЬ

Производительность считается обязательным требованием.

Обязательно:

- оптимизация изображений;
- lazy loading;
- минимизация JavaScript;
- минимизация количества запросов;
- оптимизация шрифтов;
- минимизация лишних зависимостей.
